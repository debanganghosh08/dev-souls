**Decided myself**
- `Game` is reached via `get_node_or_null("/root/Game")` + `_inject()`, not the `Game` global: the runner executes inside
  `SceneTree._init()` where autoloads do not exist yet (probed: main loop null, root not in tree), so the global would be Nil.
  Mirrors `Game._inject` for SaveGame. Cost: those accesses are dynamic (unsafe) rather than statically typed.
- In-process physics is impossible in this runner (nodes added to `root` in `_init()` never enter the tree: no `_ready`, no space), so
  `test_player.gd` tests structure + fall logic out-of-tree and spawns `godot --headless greybox.tscn -- --probe` (~3 s) for real physics.
- Extra file `scenes/levels/greybox.gd` (script next to its scene, per AGENTS.md) instead of a built-in script: sets Game→PLAYING, feeds
  the readout, debug keys Esc (PLAYING↔PAUSED, frees mouse) and E (`Game.respawn()` when DEAD, else the owner is stuck), `--probe` prints.
- Extra exports beyond spec: dodge_invulnerable_fraction, stamina_*, start_pitch_deg, target_path. Class names added for typing.
- Gravity accumulates only while airborne (velocity.y zeroed on floor), the standard Godot 4 pattern; dodge starts need floor.

**Not right yet / not covered** (honest list)
- Feel is untested by anyone: headless proves logic only. Every number above is a first guess for the owner to tune.
- Stairs: the 0.25 m steps are NOT climbable by a 0.35 m capsule (contact normal > floor_max_angle) and CharacterBody3D has no
  step-up. Expect to get stuck on the staircase; needs a step-up pass or ramp colliders under stairs (proposed follow-up task).
- Untested (need input, a window, or a live tree): dodge, sprint drain, camera-relative input, mouse look, SpringArm pull-in,
  respawn teleport, shake, freeze on PAUSED. Physics interpolation is off (project setting, not mine): >60 fps may stutter.
- Death leaves the body where it fell with no UI; `docs/TASKS.md` not marked REVIEW (outside the allowed file list).
