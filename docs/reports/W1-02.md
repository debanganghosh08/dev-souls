## Decisions I made (not in the spec)
- Injection: `SaveGame._inject(flags, inventory, game)`, `Game._inject(save)`; `_ready` fills from
  `/root/<Autoload>` only when nothing was injected. Tests call `Inventory._load_definitions()` directly.
- `Game.time_of_day` setter `fposmod`s into `[0, 24)`, so direct assignment wraps too (24.0 -> 0.0). Default 08:00.
- A manual `save()` also resets the 5 s autosave throttle. `request_autosave()` only sets a flag; the write
  happens in `_process`, so autosave (and `playtime_seconds`) only tick while the node is in the tree.
- `load_slot` type-checks every key (and `x/y/z` on vectors) before touching state; a missing key = corrupt.
  Flags are saved as strings and converted back to `StringName`. `delete()` on a missing file is a no-op.
- Test files extend `test_case.gd` by path (not `class_name`) so the suite never depends on the class cache.

## Gaps / things to know
- Atomic write: Godot's Windows `rename_absolute` deletes the destination before renaming, so there is a tiny
  window with no save file (never a corrupt one). `.tmp` is removed only on a successful rename.
- `Game.set_respawn` does not touch `state`; a future shrine system decides whether resting pauses the game.
- Untested: `_ready` autoload wiring (needs a running project). Lead should confirm once in the editor that
  `/root/SaveGame` resolves the other three and an autosave lands after `set_respawn`.
- `AGENTS.md` calls the save autoload `Save`; `project.godot` registers `SaveGame`. Code and spec use `SaveGame`.
