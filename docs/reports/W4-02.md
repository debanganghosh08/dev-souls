**Overlay ownership rule** (comment atop `main.gd`): an overlay — pause menu, lore card, inventory panel, item card — may take the screen **only while
`Game.state == PLAYING`**; whoever moved PLAYING → PAUSED is the only one that moves it back and recaptures the mouse, on its own `close()`. So at most one
holds the screen, none opens over DEAD or MENU, and Tab/Esc/E aimed at a foreign overlay do nothing. Death screen and HUD never touch state or mouse
(`kill_player` fires only from PLAYING, so nothing is open at death); Main alone does MENU ↔ PLAYING. Layers: HUD 1 < death 10 < card 12 < inventory 15 < pause 20.
**InventoryPanel** (CanvasLayer, ALWAYS): `bind_player(p)`, `open()` (refuses unless PLAYING), `close()`, `is_open()`, `row_count()`, `unknown_count()`,
`request_equip(id) -> bool` (`player.get_melee().equip`, silent on false; also from Enter/click on a held weapon row and the `%Equip` button, which reads
"Equipped"/disabled for the current one), signals `opened`/`closed`, `_inject(game, inventory)`. Tab opens in `_unhandled_input`; Tab/Esc close and W/S move
focus in `_input`, because a focused Button lets the Viewport eat Tab as `ui_focus_next` first (the probe's injected `InputEventAction` would not have shown
that; a real key would). Arrows use Button focus neighbours, `follow_focus` scrolls, hover focuses (= selects) a row. Fade in 0.2 s. Rows rebuilt per open.
**InventoryRows statics:** `build_rows(definitions, counts)` → rows {id, kind, name, lore, slot, order, count, held}, one per definition, undefined ids in
`counts` skipped; `row_before(a, b)` (kind rank → `order` → id); `kind_rank` (`KIND_ORDER` kindling, fragment, key, tool, lore; unknown kinds after,
alphabetical); `group_rows` → [{kind, rows}]; `progress` → (held distinct, total); `kindling_progress` → (distinct kindlings held, defined); `unknown_count`;
`is_weapon` (`slot == "weapon"`); `title_for` (name, `name ×n` past one, or `???`); `body_for` (lore or "Not yet found."); `kind_label` (`kind_<kind>` key).
**Kindling count** is `Inventory`-derived (distinct `kind == "kindling"` ids held, "Kindling n of 3"): it is what the player carries, and `Flags.count_with_prefix` would need a flag naming scheme nobody has defined, which I would have had to invent.
**ItemCard** (Control): `fill(title, kind, count_line, body)`, `present(id)`, `close()`, `is_open()`, `shown_id()`, `pending_count()`, `static seen_flag(id)`
→ `seen_item_<id>`, `embedded` export (detail pane: no dim/hint/input, never touches state), `_inject(game, flags, inventory)`. On `Inventory.item_added`
it queues unseen ids; shows at once if PLAYING, else on the next `state_changed` → PLAYING (deferred), one after another; E/Esc dismiss; flag set on show.
**Flag, not runtime set:** Flags are what SaveGame already serialises, so a Continue tomorrow knows what was shown, a second copy of a known item (another
torch, a kindling after respawn) only toasts, and New Journey (fresh flags) shows every card again. A runtime set would replay cards every session.
